# Peck 更新策略

Peck 的首版应用内更新只支持 macOS `.app` 安装包。

默认行为：

- 自动检查新版本默认开启。
- 默认检查渠道为 GitHub；用户可以切换到 CNB。
- 只检查稳定 Release，不处理 draft 或 prerelease。
- 自动检查只访问 Release 元数据，不自动下载、不自动退出，也不自动替换当前应用。
- 发现新版本时，弹出独立的应用级更新窗口，不要求用户先打开设置页，也不在设置页内绘制遮罩弹窗。
- 更新窗口使用原生标题栏，不会因失焦关闭；包含可滚动的 Markdown 更新说明、发布页入口、下载进度和重启升级入口。
- “稍后处理”、Escape、⌘W 或关闭按钮会关闭并释放更新窗口；本次运行不再自动提示同一版本，手动检查仍可重新提示。
- 用户点击更新操作后，才会下载当前 CPU 架构对应的 `.zip`。
- 下载包必须来自 GitHub 或 CNB 的 HTTPS 地址，并通过资产大小和 SHA-256 校验。
- 校验通过后进入“待应用”状态，用户再次点击“重启并升级”才会启动 helper。
- 当前应用不是位于可写的 macOS `.app` Bundle 中时，只能查看版本和打开 Release 页面，不能原地升级。
- `.dmg` 用于人工安装，不用于应用内自动升级。

GitHub 与 CNB 使用统一的 Release、Asset 和更新状态模型。CNB 渠道沿用 `kite-desktop` 的地址改写方式：Release 元数据使用 GitHub API 获取，展示页、下载包和 checksum 地址按用户选择切换到 CNB 镜像。
